# Praeko Studio: making a video with your own agent

You (the agent) need a **terminal (shell)** to render: without one (e.g. Claude Desktop with no shell) the person can use the local Studio MCP server (`@praeko/studio-mcp`, https://praeko.app/docs/studio/mcp), which still needs Node, Chrome/Remotion and the person's own keys on their machine; that local server never publishes (publishing is the remote `praeko` MCP); say so to the person instead of improvising. You (the agent) run Praeko Studio **on the person's machine**: you write the script and `episode.yaml`, run the commands and hand over the files. The person pays for the voice, the render and their own agent; Studio never calls a language model. Open the session **in the project folder** (where `brand.json` is). The command is `npx @praeko/studio@0.4.0 <command>`, run in the project folder (`praeko studio <command>` also works when the person has the `praeko` CLI, @praeko/cli, installed).

Full docs for the installed version: `npx @praeko/studio@0.4.0 docs` (list) and `npx @praeko/studio@0.4.0 docs episode-yaml`, `long-yaml`, `style`, `from-video`, `transcription`, `voice`, `publish`, `hyperframes`. When unsure about the YAML format, read it first. `npx @praeko/studio@0.4.0 doctor` checks the environment (Node, ffmpeg, Chromium, fonts, keys, network).

When you start, run `npx @praeko/studio@0.4.0 doctor` and read each line marked as error or warning. If Node 22+, ffmpeg or ffprobe is missing, or Chrome is not downloaded yet, tell the person what is missing and PROPOSE the install command for their system (the doctor prints it under the line; macOS: `brew install node ffmpeg`; Debian/Ubuntu: `sudo apt install ffmpeg`; Chrome for Remotion: `npx remotion browser ensure` in the project folder). Wait for the person's yes, then run it and run the doctor again to confirm. Never install anything without the yes, never run `sudo` without warning first, and never ask for or read keys. Windows and Linux are untested: say so and point to the official site when unsure.

## First: the brand brief (before the first script)
- If `brief.md` exists in the project, **read it, and `playbook.md`, before writing any script** and follow them. Where the playbook says `TODO`, complete it (below) and tell the person what you filled in.
- If `brief.md` does **not** exist, run the same interview as `npx @praeko/studio@0.4.0 init`, **by talking**: short questions, **one at a time**, each skippable, in this order: language (pt|en), channel name, handle, **source** (`script`: Studio voices a script; `video`: the person edits a video they recorded; both are fine), what the channel is about (one sentence), who it is for, tone of voice (one sentence), **formats** (`short`, `long`, `carousel`, `image`, as many as they want; the first is the main one), **visual style** (2D: `flat`, `minimal`, `neon`, `comic`, `chalkboard`, `pixel`, `8bit`, `retro-crt`; 3D: `clay-3d`, `blocks-3d`, `retro-3d`, `cinema-3d`; or another one in their words; advise 1 or 2 for identity, more is allowed; the first is the channel's style), **editing style** (pace `calm`/`fast`, captions `word`/`phrase`/`none`, effects `shake`/`zoom`/`flash`/`none`, sound `sfx`/`none`, who appears `mascot`/`none`, plus `face` only when the source includes `video`; say which ones Studio applies (word captions, the effects, the sound effects) and which ones are instructions for you), colors (accent and background, hex) and font, 0 to 3 references (a URL or a description, plus what the person liked: pace, opening, look, captions, or their own words), and the voice (name/alias and provider only; skipped when the source is only `video`; **never ask for a key**). Offer each list numbered; the person answers with numbers or names. If a `brand/` folder sits next to the project (`../brand/build/tokens.json`), read it (never copy it out) and offer its colors and font as the defaults. Then record the answers with `npx @praeko/studio@0.4.0 brief --yes` and the answer flags (`--source`, `--about`, `--audience`, `--tone`, `--format`, `--style`, `--style-other`, `--pace`, `--captions`, `--effects`, `--sound`, `--face`, `--accent`, `--background`, `--font`, `--reference`, `--reference-note`, `--voice-alias`, `--voice-provider`): it writes `brief.md`, the `playbook.md` draft (the TODOs are yours) and the `brand.json` fields, including the `style` block that the engine reads (`style.visual[0]` is the channel's look). Show the person what was written and **only then** make the first video. `npx @praeko/studio@0.4.0 brief` reopens the interview from the terminal (it keeps a `.bak` of brief.md and never overwrites an edited playbook.md); `brief --only style` reopens only formats, visual style and editing style, and a new visual style never replaces a color or font the person changed.
- References: study each one with the tools **you** already have (open the page, read the transcript or captions, look at frames). Studio does not download or analyze video. Write what you find in `playbook.md` as **rules** (pace, how it opens, caption style, length), never as a copy of someone's video: no reusing their script, structure beat by beat, footage or voice. If you cannot access a reference, say so and leave the `TODO`; never invent an analysis of a video nobody watched.

## Short workflow
1. `npx @praeko/studio@0.4.0 new <slug> --title "…"` creates `episodes/<slug>/` (script, publication.json, episode.yaml, scenes.tsx, cover) and registers it in `src/Root.tsx`.
2. Check every fact against its source and write `script.txt`. **The person approves the text before any spend** (final voice).
3. `npx @praeko/studio@0.4.0 voice <slug> --quality draft`: **estimated, silent** voice (free, instant, no network) to assemble scenes. Not publishable: `check` warns while the voice is estimated. When the cut looks right, `--quality final` (ElevenLabs, spends the person's own characters: see `npx @praeko/studio@0.4.0 voice balance`) and run `compile` again (timings change).
4. Write scenes in `episode.yaml`: each item ties to a spoken phrase with `when: "phrase"`. `npx @praeko/studio@0.4.0 compile <slug>`: error = phrase not in the voice, invalid type or color, comma without quotes inside `{ }`; warning = item overflowing the panel or overlapping. What YAML cannot express goes in `scenes.tsx` via `component:`.
5. `npx @praeko/studio@0.4.0 check <slug>`, `npx @praeko/studio@0.4.0 render <slug> --scale 0.5` (preview) and `npx @praeko/studio@0.4.0 contact-sheet <slug>` (frame mosaic: **look at the image**, do not trust the code alone).
6. Final `npx @praeko/studio@0.4.0 render <slug>`, `npx @praeko/studio@0.4.0 cover <slug>`, fill `publication.json` and run `npx @praeko/studio@0.4.0 package <slug>` (writes `texts.md`, checks limits and the AI disclosure).
7. **Review before asking for approval** (after `package`, never skipped): run `npx @praeko/studio@0.4.0 review <slug>` (without a shell, the MCP tool `studio_review` returns the same package, the frames as images). It writes `out/<slug>-review/`: `frames/` (JPEGs with the time in the name: the opening at 0 to 2 s, one per scene, one every 2 s, the last), `manifest.json` (measured facts and findings) and `REVIEW.md` (your instructions). Studio calls no model: **you** are the reviewer. Read `REVIEW.md` and the manifest, then **LOOK at the frames in order** (open each image; do not review from the findings alone), confront the measured findings with what you see, and write the review in the format of `REVIEW.md` (one line per moment: `0:02 — problem — suggestion`, then a verdict with exactly three priorities). Say what the stills cannot show (movement, fine sync, audio beyond the measures) instead of guessing. Show the review to the person **before** asking for approval; apply the changes they approve (edit, compile, render, review again), and only then go on to publishing.
8. Long form (16:9): `npx @praeko/studio@0.4.0 new <slug> --long`; vertical cuts: `npx @praeko/studio@0.4.0 cut <long> <slug> --from … --to …`.

## The person's own video (edit a video they recorded)
- `npx @praeko/studio@0.4.0 new <slug> --from-video <file.mp4> [--lang pt|en]` (MCP: `studio_new_episode` with `fromVideo`) copies the video to `public/video/` (the original is never changed; `public/video/` stays out of git), transcribes it **on this machine** into `words.json`/`words.ts` (the cloud only with `--cloud`, if the person asks; `--transcript <file.json>` reuses a transcript), and writes `episode.yaml` with the video as `base` (it plays under every scene with its own sound): **no `voice:`, no `outro`, no voice to make**. Read `npx @praeko/studio@0.4.0 docs from-video` first.
- Then add scenes and items as usual (`when` takes phrases of the video as the transcript wrote them; numbers may come as digits). It warns about words with zero duration and digits: check them in `words.json`, or spell them out with `captionFixes` in `brand.json`. `npx @praeko/studio@0.4.0 render <slug> --seconds 10` renders only the first 10 s for a quick look; `check` counts the words of `words.json`, not of a script.
- Without local Whisper the command says how to get it: `npx @praeko/studio@0.4.0 transcribe --download-model` (about 547 MB) **only after the person's yes**. `publication.json` starts with `"ai": { "synthetic": false }` (a recorded video); change it if the video has a synthetic voice or a generated person.

## Image posts and carousels (Instagram)
- `npx @praeko/studio@0.4.0 new <slug> --image` creates an **image piece**: `episode.yaml` with `format: image` and ONE slide (`slides:`). For a **carousel** use `npx @praeko/studio@0.4.0 new <slug> --carousel`: `format: carousel` and 2 to 20 slides, posted in the order of the list (slide 1 first); each slide has its own items, `alt` and optional `title`, and Instagram crops every slide to the proportion of the FIRST one (all are 1080x1350, so they match). The slide reuses the items of a cover (text, big, box, line, bar, stack, row, card) and has an `alt` text (required, up to 1000 characters; it describes the image for people who cannot see it). No script, voice or video.
- `npx @praeko/studio@0.4.0 slides <slug>` renders `out/<slug>-slide-01.jpg`, `-02.jpg`… (one per slide): 1080x1350 (4:5), sRGB JPEG, Remotion only (HyperFrames has no image mode); each slide has a time limit (`--timeout`, 180 s) and a failed one is named. `check` needs the alt text of every slide and the JPEGs (size 1080x1350, at most 8 MB); `package` writes `images` (file and alt, in slide order) into publication.json and `texts.md` (Instagram caption and alt text only).
- **Review the slides too**, before asking for approval: `npx @praeko/studio@0.4.0 review <slug>` (or `studio_review`) reduces each slide to `out/<slug>-review/frames/slide-NN.jpg` and measures size, contrast, alt text (length, repetition, generic or unrelated to the slide) and the brand's forbidden phrases. LOOK at each slide in order, read `REVIEW.md`, write the review (`Slide 2 — problem — suggestion`, then a verdict and three priorities), show it to the person, and only then go on.
- Only Instagram takes it for now (YouTube has no image posts; TikTok photo mode is a later phase). Publish: `npx @praeko/studio@0.4.0 schedule <slug> --via praeko --when "…"` simulates (`--send` publishes: never without a yes); through the MCP, `studio_upload` returns the media id of each JPEG (a carousel: ALL the slides, in order, at most 20 files and 100 MB) and the remote `create_post` takes `kind: "image"` or `"carousel"` with `media.images: [{ media, alt }, …]` in that order. The alt text goes to Instagram through Meta (`via: meta`, on every slide); Instagram publishes through Meta.

## Transcribing a video or audio the person already has
- Use it to understand or reuse a file that was NOT made here (a recording, an interview, a reference the person owns): subtitles, finding a moment, a cut, a text post. Not for videos Studio made: those already have their script and word timings.
- `npx @praeko/studio@0.4.0 transcribe <file> [--lang pt|en|auto]` (MCP: `studio_transcribe`) runs on the person's machine and writes `transcript.json` (words with start and end times, language, engine, engines tried), `transcript.srt` and `transcript.txt` next to the file. Nothing goes up to Praeko.
- **Read only what you need.** The command and the tool answer with a summary and a short preview: do not paste the whole text into the conversation. For a long file, read `transcript.txt` in pieces, or search `transcript.json` for the words around a time, and quote short excerpts with their time (`0:42 — "…"`). Say what you did not read.
- Local first: VoiceStudio, then local Whisper. If no local model exists, the error says how to get it. `npx @praeko/studio@0.4.0 transcribe --download-model` downloads one (about 547 MB, from Hugging Face, SHA-256 checked): **ask first and run it only after the person's yes** (it also needs `--yes` when you run it without a terminal).
- The cloud engine (ElevenLabs Scribe) sends the audio away and spends the person's credit: use `--cloud` only if the person asked for it. The MCP tool cannot turn it on. If the transcript looks wrong (loops, wrong language), say so and try `--lang` before trusting it.

## Text rules
- Spoken text: short sentences, numbers spelled out, addresses as spoken (`pronunciation` in `brand.json`), few English emotion tags (`[curious]`, `[confident]`, `[short pause]`), about 190 words per minute.
- No real person's name without consent (`bannedNames` in `brand.json`). Every number has a source; anything unmeasured is called an estimate.
- Brand style rules live in `brand.json`, `brief.md` and the project's `playbook.md`. `package` flags AI writing tics (`publishing.aiTics: false` in `brand.json` turns it off).
- Phrases the brand must never say (promises it cannot keep) go as quoted bullets under a `## Never say` heading in `playbook.md`, or in `review.forbiddenPhrases` of `brand.json`: `npx @praeko/studio@0.4.0 review` flags them in the script, captions, on-screen text and publication texts.

## Voice, costs and secrets
- Keys **never** in project files, logs or chat: `echo $KEY | npx @praeko/studio@0.4.0 voice config key elevenlabs/principal` stores it in the OS keychain (macOS) or in `~/.config/praeko/secrets.json`; `ELEVENLABS_API_KEY` and `PRAEKO_KEY` also work.
- Use **only the person's own voice** or a voice they are authorized to use. Before `--quality final`, show the text and the balance and wait for a yes.

## AI content disclosure (required in the package)
- Fill `"ai": { "synthetic": true|false }` in `publication.json`. A realistic synthetic voice, or generated image/video that looks real, requires the altered/synthetic content label on YouTube, "AI info" on Instagram and the AI-generated label on TikTok. `npx @praeko/studio@0.4.0 check` and `package` warn when it is missing.
- YouTube receives the field through Studio's direct upload; through Praeko and on Instagram/TikTok **the person sets the label in the network's app** before publishing. Put that in the "before publishing" list.

## Publishing through Praeko (only after the person's yes)
Nothing is published unless the person says so. Two ways:
1. **CLI:** `npx @praeko/studio@0.4.0 schedule <slug> --via praeko --when "dd/mm hh:mm"` only **simulates**. `--send` really publishes: never use it unless asked.
2. **Praeko MCP** (if connected to your agent): local file, in one step `create_media_upload { type, name, mime, size }` (size in bytes: `wc -c < file`), upload with the returned `curl`, then `complete_media_upload { mediaId }` until `ready`. Then `create_post`/`schedule_post` with **mandatory two steps**: the first call returns only the **preview** and a `confirmation_code`; **show the whole preview to the person** (channels, time in BRT/UTC, media, texts, warnings), wait for explicit approval, and only then repeat the call with the same arguments plus `confirm`. Never confirm on your own.
Praeko key (`write` scope): get it with `npx @praeko/studio@0.4.0 login` (sign-in by code: give the person the code and the address it prints, they approve in the browser; the key goes to the project's profile in `.praeko/config.json` and you never see it). Plan B, in the person's OWN terminal: `npx @praeko/studio@0.4.0 setup --key` (hidden input; never ask for the key) or `echo $KEY | npx @praeko/studio@0.4.0 schedule --via praeko --key`.

## Render engine
Remotion is the default engine for videos AND covers (and for `scenes.tsx` pieces); `--engine hyperframes` renders videos and covers with HyperFrames (Apache-2.0, fetched with npx on first use) and uses nothing from Remotion (scenes and covers with `component:` only render in Remotion). Remotion has its own license: free for individuals and companies up to 3 people; see the notice in `npx @praeko/studio@0.4.0 doctor`.

## Old projects
A project from Studio 0.1.x (Portuguese file and key names) is converted once with `npx @praeko/studio@0.4.0 migrate --dry-run`, then `npx @praeko/studio@0.4.0 migrate`.
